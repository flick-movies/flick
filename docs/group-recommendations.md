# Group Recommendations

## Status

**Planned — not yet implemented.**

This document describes the intended role and design requirements for Flick's group recommendation system. The final algorithm should be documented here as implementation decisions are made.

## Purpose

Group recommendations will allow Flick to recommend movies for multiple users at the same time.

Instead of answering:

> Which movie will one user enjoy most?

the group recommender must answer:

> Which movie gives this particular group the best overall viewing experience?

The system should avoid recommendations that one person loves but another person strongly dislikes unless the group explicitly chooses that behavior.

## Inputs

Expected inputs include:

* Two or more user IDs
* Each user's rating history
* Candidate movies
* Individual recommendation scores generated by Flick's recommendation models
* Optional filtering constraints such as genre, runtime, streaming service, or release year

## Outputs

The group recommender should eventually return a ranked list of movies containing information such as:

* Movie ID
* Movie title
* Group recommendation score
* Individual predicted scores for each member
* Explanation of why the movie works for the group
* Potential disagreement or fairness information

The exact output schema has not yet been finalized.

## Core Idea

The group system will build on Flick's individual recommendation models rather than replacing them.

A likely pipeline is:

1. Generate or obtain an individual preference score for every user and candidate movie.
2. Combine those individual scores using a group aggregation strategy.
3. Penalize candidates that create severe disagreement if appropriate.
4. Apply diversity or other final reranking rules.
5. Return the strongest group recommendations.

The main design question is how individual preferences should be combined fairly.

## Algorithm Flow

The exact algorithm has not yet been selected.

A future implementation will likely follow this structure:

### 1. Generate candidate movies

Build a candidate pool that excludes movies already watched by members when appropriate.

### 2. Score each candidate for every group member

Use Flick's individual recommendation pipeline to estimate how strongly each person would prefer each movie.

Conceptually, each candidate would receive a vector such as:

`[user_1_score, user_2_score, user_3_score, ...]`

### 3. Aggregate the individual scores

Possible aggregation strategies include:

* Mean score
* Median score
* Minimum score
* Weighted mean
* Least-misery methods
* Satisfaction-based methods
* Fairness-aware optimization

These approaches have different tradeoffs and should be evaluated rather than selected only by intuition.

### 4. Account for disagreement

The model may include a penalty for high disagreement between group members.

For example, two candidates could have the same mean score while producing very different experiences:

Movie A:

`[4.5, 4.5, 4.5]`

Movie B:

`[5.0, 5.0, 3.5]`

A group-aware system may want to distinguish between these cases even though their average enjoyment is similar.

### 5. Apply final reranking

The final list may incorporate:

* diversity
* fairness
* genre repetition
* group disagreement
* group-specific filters

### 6. Generate explanations

Recommendations should eventually explain why a movie was chosen for the group.

Examples could include:

* strong match for every member
* especially strong match for two members with no strong dislike from the third
* compatible with genres enjoyed across the group

The explanation system has not yet been implemented.

## Features / Signals

Potential group-level signals include:

* Mean individual recommendation score
* Minimum individual recommendation score
* Median score
* Standard deviation between users
* Maximum disagreement
* Number of users predicted to strongly enjoy the movie
* Number of users predicted to dislike the movie
* Genre compatibility across users
* Collaborative-filtering predictions
* Content-model predictions

No final feature set has been selected yet.

## Training

Not currently implemented.

The first version may not require a separately trained group model and may instead aggregate scores from the individual recommendation system.

A learned group-ranking model could be explored later if sufficient group preference data becomes available.

## Inference

Not currently implemented.

The intended inference pipeline is:

`individual recommendations → group aggregation → fairness/disagreement handling → final reranking`

## Evaluation

A group recommender cannot be evaluated only by individual ranking accuracy.

Possible future metrics include:

* Average predicted group satisfaction
* Minimum-member satisfaction
* Recommendation acceptance rate
* Fairness between members
* Variance in predicted enjoyment
* NDCG or ranking accuracy using group preference data
* Comparison between aggregation strategies

A proper evaluation design will be added when the first group algorithm is implemented.

## Important Hyperparameters

No final group-recommendation hyperparameters currently exist.

Potential future parameters may control:

* Weight placed on average satisfaction
* Penalty for the least-satisfied member
* Disagreement penalty
* Diversity penalty
* Relative importance assigned to different users when weighting is enabled

## Known Limitations

The group recommender is not yet implemented.

Important challenges that the implementation will need to address include:

* Fairly combining conflicting user preferences
* Avoiding domination by one group member
* Handling users with very different amounts of rating history
* Handling movies already watched by only some members
* Avoiding overly safe recommendations that nobody dislikes but nobody strongly enjoys
* Evaluating group recommendations without large amounts of real group-choice data

## Future Improvements

Once a basic version exists, possible extensions include:

* Adjustable group decision styles
* Voting-based recommendation modes
* Fairness-aware optimization
* Learned group preference models
* Group taste profiles
* Explanations showing each member's predicted reaction
* Integration with friends and social features
* Group watch-history tracking
* Real-time group voting before a recommendation is selected
